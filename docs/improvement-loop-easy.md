# 개선 루프 쉽게 보기

결과를 보고 규칙을 고치는 과정을 쉬운 말로 풀었다. 정확한 동작과 수치는 [분석·개선 루프 동작 방식](improvement-loop.md).

## 한마디로

> **AI가 "여기가 문제고, 이렇게 바꿔 보면 어때요?"라고 제안하면, 컴퓨터가 미리 돌려서 효과를 보여주고, 사람이 "좋아, 바꾸자"를 결정한다.**

회사로 치면 이렇다.

| 역할 | 비유 | 하는 일 |
|---|---|---|
| 분석 AI | 분석 담당자 | 실적 자료를 보고 "어디서 자꾸 문제가 생기는지" 찾아온다 |
| 개선 AI | 기획 담당자 | "규칙을 이렇게 바꾸면 나아질 것 같다"는 안을 낸다 |
| 컴퓨터 | 검증 담당자 | 숫자가 맞는지, 규정 안의 변경인지 확인하고, 미리 돌려서 결과를 보여준다 |
| 사람 | 팀장 | 좋아지는 점과 잃는 점을 보고 채택할지 정한다 |

## 예시로 한 바퀴

상황: 서울 강남3구에서 기사님께 출동 일정을 배정하는데, 1500건 중 460건(약 30%)이 배정되지 못했다.

**① 문제 찾기 (분석 AI)**

AI가 자료를 이리저리 나눠 보다가 눈에 띄는 곳을 찾는다.

> "관할 구역 **가장자리** 주소는 두 건 중 한 건꼴로 배정이 안 됩니다. 대부분 '기사님이 갈 수 있는 거리 밖'이라서요. 안쪽 주소는 여섯 건 중 한 건꼴입니다."

이때 AI가 숫자를 지어내지 못하게, 말한 숫자가 실제 자료에 있는지 컴퓨터가 확인한다.

**② 해결책 내기 (개선 AI)**

> "가장자리 주소만, 기사님이 갈 수 있는 거리를 1km 늘려 봅시다."

허용된 범위를 넘는 안(예: "거리를 확 늘려서 9km로")은 컴퓨터가 바로 돌려보낸다.

**③ 미리 돌려보기 (컴퓨터)**

실제로 바꾸기 전에 같은 자료로 다시 배정해 본다. 몇 초면 끝나고 돈도 들지 않는다.

| | 바꾸기 전 | 바꾼 후 |
|---|---|---|
| 배정 성공 | 10건 중 7건 | 10건 중 **8건** |
| 가장자리 주소 실패 | 두 건 중 한 건 | **네 건 중 한 건** |
| 고객이 원한 시간에 맞춘 비율 | 약 70% | 약 60% ↓ |

좋아진 점도 있고 잃는 점도 있다. 더 많이 배정되지만, 멀리서 오느라 고객이 원한 시간은 덜 지킨다.

**④ 결정하기 (사람)**

팀장이 표를 보고 "배정률이 더 중요하다"고 판단하면 승인한다. 승인하면 규칙 파일이 새 버전으로 바뀌고, 다음 실행부터 새 규칙이 쓰인다. 아니라고 보면 반려한다.

## 왜 이렇게 나눴나

- **AI는 아이디어를 잘 낸다.** 많은 자료에서 패턴을 찾고 여러 해결책을 떠올리는 일.
- **AI는 틀릴 수 있다.** 그래서 숫자 확인과 규정 검사는 컴퓨터가 기계적으로 한다.
- **좋고 나쁨은 상황마다 다르다.** 배정률과 시간 약속 중 무엇이 더 중요한지는 사람이 정한다.

## 한 장 그림

```
 결과 ──▶ 분석 AI ──▶ 개선 AI ──▶ 미리 돌려보기 ──▶ 사람 결정 ──▶ 규칙 업데이트
          "여기가      "이렇게      "이만큼          "채택!"          │
           문제"        바꿔보자"     좋아져요"                         │
   ▲                                                                   │
   └──────────────────────── 다음 실행 ◀────────────────────────────────┘
```

> 참고: 위 예시의 분석·제안 문장은 설명용 시나리오이고, 표의 수치는 실제 규칙 엔진으로 계산한 값을 쉽게 반올림한 것이다.
