# 화면 매뉴얼

브라우저 화면(비교·트레이스·분석·개선 탭)의 구성과 사용법이다. 설치와 실행은 [README](../README.md#시작하기)를 본다.

이 문서의 캡처는 **리허설 번들**(가짜 LLM으로 미리 만든 결과, API 키 불필요)로 찍었다. 그래서 AI agent의 판단 근거가 `fake`로 나오고 수치는 AI 성능과 무관하다. 실제 API로 실행하면 같은 자리에 실제 값이 나온다. 지도 배경(OpenStreetMap)은 인터넷이 될 때만 보이며, 캡처는 오프라인 상태라 구 경계만 보인다.

```bash
python -m scripts.rehearsal_bundle              # 리허설 번들 만들기 (몇 초)
python -m api.main --demo demo/rehearsal        # http://127.0.0.1:8000
```

## 1. 화면 구성

![비교 탭 전체](images/ui/01-compare-l0.png)

| 영역 | 내용 |
|---|---|
| 상단 배너 (시연 모드일 때만) | AI 결과를 저장된 실행에서 재생 중이라는 표시, 번들 정보, **재생 가능한 AI 실행 목록**(데이터셋·레벨·건수) |
| 탭 | 도메인(규칙·데이터 조회) 다음, 비교 → 트레이스 → 분석 → 개선 순서로 쓰는 것을 전제로 한다. 앞 탭에서 만든 데이터·실행·리포트를 뒤 탭이 이어받는다 |
| 데이터 생성 줄 | seed(같은 값이면 같은 데이터), 결함 패턴 P1~P4 체크, **데이터 생성**, **실행 범위**, **규칙 agent 실행** |
| 하네스 줄 | 레벨 L0~L5 선택, 레벨이 켜는 기능 표시(✓/–), 반복 횟수, **AI agent 실행**, 모델·effort·캐시 설정 |

### 하네스 레벨

| 레벨 | 명세 | 도구 | 검증 루프 | 가드레일 | 트레이스 | 한 줄 설명 |
|---|---|---|---|---|---|---|
| L0 | – | – | – | – | 최종 결과 | 데이터만 주고 결정하게 한다 |
| L1 | ✓ | – | – | – | 최종 결과 | 도메인 명세(domain-spec.md)를 시스템 프롬프트로 준다 |
| L2 | ✓ | ✓ | – | – | 최종 결과 | 후보 조회·이동시간·일정 확인 도구를 쓰게 한다 |
| L3 | ✓ | ✓ | ✓ | – | 최종 결과 | 결정을 검증기로 확인하고, 위반이면 사유를 돌려줘 재시도하게 한다 |
| L4 | ✓ | ✓ | ✓ | ✓ | 최종 결과 | 위반은 차단, 승인 필요 조건이면 승인 대기로 보류한다 |
| L5 | ✓ | ✓ | ✓ | ✓ | **모든 단계** | L4 + LLM 응답·도구 호출·검증·재시도를 모두 기록한다 (트레이스 탭에서 볼 수 있다) |

### 실행 범위

- **1일차 앞 10건 (시범)**: AI 비용을 확인하는 첫 실행용. 리허설 번들의 AI 결과도 이 범위다.
- **N일차 (150건)**: 하루치.
- **전체 1500건**: 10일치. 규칙 agent는 비용이 없으니 전체로 돌려도 된다.

AI agent를 실행하면 **같은 범위로 규칙 agent도 함께 실행**되어 왼쪽(규칙)과 오른쪽(AI)을 나란히 비교한다.

## 2. 도메인 탭 (읽기 전용)

규칙 agent가 판단에 쓰는 **규칙과 데이터**를 본다. 여기서는 아무것도 바꾸지 않는다. 규칙은 개선 탭의 개선안과 승인으로만 바뀐다. 위쪽 버튼으로 섹션을 고른다.

| 섹션 | 내용 |
|---|---|
| 개요 | 규칙 파라미터 버전, 필수조건·차원·결함 패턴 수, 파일 위치와 역할, 현재 데이터셋 |
| 규칙 파라미터 | `params.yaml` 섹션별 표: 현재 값, 허용 범위(최솟값=최댓값이면 "고정"), 설명. 구간 조건 목록과 승인 이력(버전 변화) |
| 필수조건·사유코드·차원 | 필수조건(validate가 판정), 미할당 사유 코드(코어 사유 포함), 분석 차원 |
| 명세 | `domain-spec.md` 6개 섹션. L1 이상에서 AI agent에게 이 문장이 그대로 들어간다 |
| 데이터 | 지점·작업자·지시서 표 (검색, 드롭다운 필터, 머리글 눌러 정렬, 100건씩 더 보기). **행을 누르면 오른쪽 지도에서 위치를 강조하고 그곳으로 이동한다**: 지시서는 그날의 지시서와 함께, 작업자는 출발 위치, 지점은 관할 구역 |
| 결함 패턴 | P1~P4의 이름과 기대 현상. **정답 보기**를 누르면 주입 방식과 채점 기준이 보인다 (발표 중에는 분석 장면 뒤에 연다) |

![규칙 파라미터](images/ui/08-domain-params.png)

![데이터 표와 지도](images/ui/09-domain-data.png)

![결함 패턴 (정답 가림)](images/ui/10-domain-faults.png)

데이터 섹션은 데이터셋이 있어야 보인다. 없으면 **기본 데이터 생성**을 누른다(비교 탭의 seed·결함 패턴 설정을 쓴다).

## 3. 비교 탭

### 지도 (서울 강남3구)

![지도와 판단 근거](images/ui/03-map-detail.png)

| 표시 | 뜻 |
|---|---|
| 색칠된 구역 | 지점별 관할 구역. 파랑 = 서초지점(A), 주황 = 강남지점(B), 초록 = 송파지점(C) |
| ▪ 작은 사각형 | 작업자 출발 위치 (지점 색) |
| ● 원 | 배정된 지시서 (지점 색) |
| ✕ 빨간 X | 미할당 또는 가드레일 차단 |
| ◯ 노란 테두리 | 승인 대기 (L4·L5) |
| 선 | 작업자의 당일 동선 (출발 위치 → 배정된 지시서를 시작 시각 순으로) |

- **날짜**: 실행 범위에 포함된 날만 고를 수 있다.
- **배경 지도**: 인터넷이 되면 OpenStreetMap이 흐리게 깔린다. 체크를 끄면 구 경계만 보인다.
- 지도는 `+`/`−` 버튼으로 확대하고 드래그로 이동한다(스크롤 확대는 페이지 스크롤과 겹쳐서 껐다).
- 점에 마우스를 올리면 지시서·작업자 요약이 뜨고, **지시서를 클릭하면 아래에 판단 근거**가 나온다. 규칙 agent는 후보가 어떻게 줄었는지(지점 → 기술 → 자격 → 매칭 단계)를 문장으로 남긴다.
- 관할 구역 밖(경계 너머)에 찍힌 지시서는 P4(경계 지역 수요) 패턴이다. 관할 밖 거리가 `matching.area_extension_km`의 최대 완화 범위보다 멀면 `OUT_OF_AREA`로 미할당된다.

### 지표 카드

| 지표 | 계산 |
|---|---|
| 필수조건 위반 (사후 채점) | 레벨과 무관하게 모든 결정을 `validate()`로 다시 검사한 위반 건수. 0건이 목표 |
| 할당성공률 | 배정된 지시서 / 전체 지시서 |
| 희망시간 일치율 | 배정된 지시서 중 고객 희망시각에 정확히 시작한 비율 |
| 평균 이동시간 | 직전 위치에서 지시서까지 이동시간(직선거리 × 우회계수 1.3 ÷ 평균 30km/h)의 평균 |
| 작업자 활용률 | 작업 시간 합 / 작업자 가능시간 합 |
| 1·2·3단계 매칭 | 배정 건 중 각 매칭 단계(시간·지역 조건을 단계적으로 완화)에서 배정된 비율 |
| 건당 비용·처리 시간 | AI는 LLM 토큰 비용, 규칙은 $0 |

아래 막대그래프는 미할당 사유 코드(NO_SKILL, NO_CERT, NO_TIME_MATCH, OUT_OF_AREA, CAPACITY 등)별 건수다.

### 레벨별 비교표

![레벨별 비교표](images/ui/02-compare-table.png)

같은 데이터·같은 범위에서 실행한 규칙 agent와 AI agent(레벨별)를 한 줄씩 비교한다. 위 캡처에서 L0은 위반 2건이 남고 L3·L5는 검증 루프 덕분에 0건이다. **일관성**은 같은 레벨을 2회 이상 반복 실행했을 때 결정이 모두 같은 항목의 비율이다.

## 4. 트레이스 탭

![트레이스](images/ui/04-trace.png)

AI agent가 지시서 하나를 어떻게 결정했는지 단계별로 본다. **단계 기록은 L5 실행에만 있다** (L0~L4는 최종 결정만 기록).

1. **실행**을 L5로 고른다.
2. 항목 필터로 좁힌다: 전체 / **재시도 있음** / 차단·승인 대기 / 미할당.
3. 왼쪽 목록에서 지시서를 고르면 위에 AI agent와 규칙 agent의 최종 결정이 나란히, 아래에 단계가 순서대로 나온다.

| 단계 | 뜻 |
|---|---|
| LLM 응답 | 모델이 낸 도구 호출·결정. 토큰 사용량 표시 |
| 도구 호출 | 후보 조회·이동시간·일정 확인 등의 입력과 결과 |
| 검증 | 결정을 검증기로 확인한 결과 (✕ 위반 규칙과 메시지 / ✓ 위반 없음) |
| 재시도 | 검증기가 반려하며 모델에게 돌려준 메시지 |
| 가드레일 | 확정 / 차단 / 승인 대기 |

## 5. 분석 탭

![분석](images/ui/05-analysis.png)

분석 agent가 실행 결과를 집계 도구로 조회해 실패 패턴과 원인 가설을 낸다. 심어둔 패턴(P1~P4)을 찾는지 정답표로 채점한다.

1. **규칙 agent 전체 실행** (1500건, 비용 없음) → **분석할 실행**에서 고른다.
2. **분석 agent 실행**.

| 요소 | 뜻 |
|---|---|
| 패턴 탐지율 | 심어둔 패턴 중 찾은 비율. 정답표는 채점에만 쓰며 분석 agent는 보지 못한다 |
| 정답과 매칭 안 된 발견 | 정답표에 없는 발견. 사람이 **정당한 발견 / 오탐**으로 판정한다 (판정 대기 건수 표시) |
| 오탐 (사람 판정) | 사람이 오탐으로 판정한 건수 |
| 분석 비용·시간 | LLM 호출 수, 도구 호출 수, 비용 |
| ✓/✕ 패턴 줄 | 패턴별로 찾았는지와 매칭된 발견 ID |
| 발견 카드 | 제목, 수치 설명, 구간(차원 칩), 사유 코드, **근거**(인용한 도구 호출과 결과 표) |

- 발견 제목을 누르면 **오른쪽 지도에서 해당 구간의 지시서만 강조**되고 나머지는 흐려진다. 강조된 지시서가 가장 많은 날짜가 자동으로 선택된다.
- 발견의 수치는 인용한 도구 결과에 실제로 있는 값이어야 한다. 근거 없는 수치를 쓴 발견은 "근거 없는 수치로 제외된 발견"으로 따로 모인다.

## 6. 개선 탭

![개선안과 시뮬레이션](images/ui/06-improve-simulation.png)

분석 리포트를 바탕으로 개선안을 만들고, 시뮬레이션으로 효과를 확인한 뒤 사람이 승인한다.

1. **개선안 생성** (분석 탭에서 만든 리포트 기준).
2. 개선안마다 **시뮬레이션** → 전·후 지표 표를 본다.
   - 규칙 파라미터(params.yaml) 개선안은 규칙 엔진을 다시 돌려 즉시 비교한다(비용 없음).
   - 도메인 명세(domain-spec.md) 개선안은 AI agent를 개선 전·후 명세로 실행해야 하므로 **예상 비용을 먼저 보여주고 확인을 받는다**. 레벨과 범위를 고를 수 있다.
3. 메모를 적고 **승인** 또는 **반려**.

| 개선안 상태 | 뜻 |
|---|---|
| 제안됨 | 시뮬레이션 전 |
| 검증 실패 | 허용 범위(params.yaml의 bounds) 밖이거나 형식 오류. 이유가 빨간 글씨로 나온다 |
| 시뮬레이션 완료 | 승인할 수 있다 |
| 승인됨 / 반려됨 | 결정 완료. 승인하면 params.yaml 버전이 오른다 |
| 기준 변경됨 | 다른 개선안이 먼저 승인되어 기준 파일이 바뀌었다. 다시 제안해야 한다 |

- 개선안 종류: **규칙 파라미터**(값 변경, 또는 "경계 지역만" 같은 구간 조건) / **도메인 명세**(섹션 교체, 현재·제안 비교 펼침).
- **승인은 파일에만 반영한다. git 커밋은 사람이 직접 한다.** 시연 모드에서는 작업 복사본에만 반영되고, 서버를 다시 켜면 처음 상태로 돌아간다.
- 상단 카드: 이번 개선 1회전에 AI가 쓴 시간·비용, 같은 분석을 사람이 할 때의 추정 시간(직접 입력, 브라우저에만 저장), 반영된 회차 수.

![개선 이력](images/ui/07-improve-history.png)

**개선 이력**은 승인한 회차별 할당성공률 추이(시뮬레이션 기준)와 회차 표(개선안, 전·후, AI 비용·시간, 메모)다.

## 7. 리허설 번들로 한 바퀴

1. (선택) 도메인 탭: 규칙 파라미터와 명세를 훑어본다. 결함 패턴의 정답은 분석까지 끝난 뒤에 연다.
2. 비교 탭: P1~P4 모두 체크, seed 42 → **데이터 생성** → 실행 범위 **1일차 앞 10건 (시범)**.
3. **L0** 선택 → AI agent 실행 → 오른쪽 지도·비교표 확인 (위반 남음).
4. **L3**, **L5**도 실행 → 비교표에서 위반이 0건이 되는 것을 확인.
5. 트레이스 탭: 실행 L5, 필터 **재시도 있음** → 지시서 선택 → 검증 반려 → 재시도 → 확정 흐름.
6. 분석 탭: **규칙 agent 전체 실행** → **분석 agent 실행** → 탐지율 3/4, "경계 지역 실패" 발견을 눌러 지도 강조. 매칭 안 된 발견(F4)에 정당한 발견/오탐 판정.
7. 개선 탭: **개선안 생성** → "경계 지역만 3단계 지역 범위 +1km" **시뮬레이션** → 할당성공률 상승 확인 → **승인** → 개선 이력.

## 8. 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| "저장된 AI 실행이 없음" (시연 모드) | 번들에 없는 조건(데이터셋·레벨·범위)으로 실행했다. 상단 배너의 **재생 가능한 AI 실행**과 같게 맞춘다 (리허설 번들: P1~P4, seed 42, 1일차 앞 10건, L0·L3·L5) |
| "LLM 클라이언트를 만들 수 없음" | API 키가 없다. `.env`에 `ANTHROPIC_API_KEY`를 넣거나, 리허설 번들로 시연 모드를 쓴다 |
| 분석·개선 탭이 비어 있음 | 앞 탭의 단계가 필요하다: 분석은 끝난 실행이, 개선은 분석 리포트가 있어야 한다 |
| 개선안이 모두 승인됨·반려됨이라 다시 못 해 봄 | 시연 모드는 서버를 다시 시작하면(`Ctrl+C` 후 재실행) 처음 상태로 돌아간다 |
| 지도에 도로·지명이 안 보임 | 인터넷이 안 되거나 **배경 지도** 체크가 꺼져 있다. 구 경계와 데이터는 그대로 동작한다 |
| 트레이스에 단계가 없음 | L0~L4 실행을 골랐다. 단계 기록은 L5에만 있다 |
